# src structure

Dependency direction is one-way: `app` → `features` → shared (`components`, `hooks`, `types`, and `lib`/`config` once needed).
**Features never import each other.** Pages in `app/pages` compose them. Enforced by `no-restricted-imports` overrides in `oxlint.config.js`, which also catch relative-path bypasses (`../../other-feature`) up to one level of nesting inside a feature.

```
src/
├── main.tsx              # entry: mounts <App />
├── index.css             # global styles, design tokens, self-hosted fonts
├── app/                  # application shell + routing (the only layer that knows about everything)
│   ├── app.tsx           # <RouterProvider />, add global providers here
│   ├── router.tsx        # createRouter + type registration
│   ├── route-tree.gen.ts # GENERATED by TanStack Router plugin, do not edit
│   ├── layouts/          # chrome around pages (root-layout: header, footer), may read features
│   ├── pages/            # orchestration: one folder per page, composes features + shared UI
│   └── routes/           # file-based routes (folder structure = URL structure), render a layout or page
├── features/             # one folder per domain feature
│   └── <feature>/
│       ├── components/   # feature-only UI, one folder per component
│       │   └── <component>/
│       ├── hooks/        # feature-only hooks
│       ├── api/          # requests, query options
│       ├── store/        # client-side state / persistence
│       └── index.ts      # PUBLIC API of the feature
├── components/           # shared, domain-agnostic UI, one folder per component
│   ├── ui/               # primitives (switch, spinner, quote-card, ...)
│   └── layout/           # page/section scaffolding (header, footer, hero, ...)
├── hooks/                # shared hooks (use-flip: slide list items to their new slots)
├── types/                # shared types
└── test/                 # test-only factories, API mocks and render helpers
```

Create folders only when needed: a feature with no hooks has no `hooks/`; shared utilities and third-party wrappers go in `lib/`, env and constants in `config/` once there is something to put there.

## Component folders

Every component, shared or feature-level, is a folder named after it:

```
switch/
├── switch.tsx   # the component (named export, one per file)
├── switch.css   # its styles, imported by switch.tsx (BEM class names: switch__thumb)
└── index.ts     # export { Switch } from "./switch";
```

Anything private to a component (sub-components, tests, helpers) goes inside its folder. Consumers import the folder, never its files: `@/components/ui/switch`, not `@/components/ui/switch/switch`.

## Rules

- Files and folders: `kebab-case`. Named exports only.
- Routes are thin: they declare path, loaders and search params, and render a layout from `app/layouts` or a page from `app/pages`.
- Pages (`app/pages/<page>`) are the orchestration layer. They compose feature components, wire data between features (e.g. pass favorites state into the jokes feed as props) and own page chrome like `<main>` and `<Hero>`.
- A feature exposes components and hooks through its `index.ts`; routes, layouts and pages import a feature only through it (`@/features/jokes`), never its internals.
- Inside a feature use relative imports; use `@/` for anything outside it.
- Features do not import `app` or other features. A feature needing something owned by another feature takes it as props or callbacks, so the page wires it.
- If two features need the same data or API, extract an **entity** (`src/entities/<entity>`: model, API, store) that both may import. Entities import only shared code. Until then, shared domain types live in `types/`.
- Shared code never imports `app` or `features`.

## Routing (TanStack Router, file-based)

| File                       | URL                   |
| -------------------------- | --------------------- |
| `routes/__root.tsx`        | root layout           |
| `routes/index.tsx`         | `/`                   |
| `routes/about.tsx`         | `/about`              |
| `routes/posts/index.tsx`   | `/posts`              |
| `routes/posts/$postId.tsx` | `/posts/:postId`      |
| `routes/_auth/route.tsx`   | pathless layout       |
| `routes/posts/route.tsx`   | layout for `/posts/*` |

`route-tree.gen.ts` regenerates on `npm run dev` / `npm run build`.

## Testing (Vitest + Testing Library)

`npm test` runs everything once, `npm run test:watch` re-runs on change.

- **Colocated:** each file has `<name>.spec.ts(x)` next to it. A component folder also holds `<name>.factory.ts` with its props factory (`createSwitchProps`). Barrel `index.ts` files and the generated route tree are not tested.
- **Factories** (`@/test/factories`): `createFactory(() => ({ ...defaults }))` returns a function that builds a fresh object per call and shallow-merges overrides, so an override replaces a whole top-level property. Defaults are a function so nested objects, sequence ids and `vi.fn()` mocks are never shared between objects or tests. Props factories look like `createQuoteCardProps({ isFavorite: true })`; data factories are `createJoke`, `createJokes(n)` and `createRandomJokeResponse` (its shape is checked against a captured live response in `api.spec.ts`).
- **API mocks** (`@/test/mocks`): the app's `fetch` is stubbed to resolve requests with MSW handlers. `handlers.ts` holds the happy-path defaults; override per test with `server.use(http.get(RANDOM_JOKE_URL, () => HttpResponse.json(...)))`. Requests without a handler fail the test, even if the app swallows the error. (`setupServer()` is not used: it intercepts sockets and aborted requests leak uncaught TLS errors into later tests.)
- **Utilities** (`@/test/utils`): `renderWithRouter` for components that use `<Link>`, `captureInterval` to fire the 5s auto-refresh tick on demand, `seedFavorites` / `readStoredFavorites` for persisted favorites.
- Tests run with the same React Compiler transform as the app and inside `<StrictMode>`, like `main.tsx`. `App` takes an optional `router`, so each test gets an isolated in-memory router (`createAppRouter(createMemoryHistory(...))`) instead of sharing the singleton.
- Test behavior a user or consumer can observe (roles, text, persisted data, network calls), not implementation details.
